# Аудит изменений v0.1.0..0.3.0: безопасность и качество кода

Дата: 2026-10-18, исходный коммит 1be680c (0.3.0 и ползунок фона строк, ADR-0026). Прошлые аудиты: [security-audit-2026-10-15.md](security-audit-2026-10-15.md) (безопасность, v0.1.0) и [code-review-2026-10-16.md](../code-review-2026-10-16.md) (качество кода).

Проверялись только изменения после v0.1.0: `git diff v0.1.0..HEAD`, около 70 коммитов и 390 файлов.

Два независимых аудита:
- Claude: находки K1–K5 («проверено, в порядке») и C1–C4.
- Muse через оркестрацию Orca. Сначала свой аудит, не видя находок Claude (M1–M20), затем проверка находок Claude.

## Итог
Критичных и серьёзных находок нет. Новых разрешений, экспортированных компонентов и зависимостей времени выполнения нет. Секретов, личных данных и локальных путей в изменениях нет.

Исправлены:
- одна находка про управление своими данными (C1);
- неточные тексты приватности (C2, M5, M6);
- три мелкие защитные правки (M2, M3, C3).

## Проверено, нарушений нет
- **Манифест.** Изменились только имя класса `Application` и `android:localeConfig`. INTERNET, QUERY_ALL_PACKAGES и READ_MEDIA_* нет.
  - Экспортированные сервисы защищены системными разрешениями.
  - Приёмник времени — `RECEIVER_NOT_EXPORTED`, у `PendingIntent` стоит `FLAG_IMMUTABLE`.
  - Задача `:app:checkReleasePermissions` проходит (K1, M10).
- **Зависимости.** Добавлены только `ui-tooling-preview` и `ui-tooling`, последняя только в debug. В release-сборку попадают одни аннотации `@Preview`. Material, Coil, Hilt и Navigation отсутствуют (K2).
- **Секреты и автор коммитов.** Все коммиты от одного noreply-адреса. `mushin-lab@proton.me` — намеренно опубликованный контакт поддержки (K3).
- **Фоновые изображения.** Выбираются только через системный Photo Picker, декодирование ограничено 16 Мп. Файлы называются `space_<id>.webp` с числовым id, запись атомарная (через временный файл и переименование). Резервное копирование и перенос их не включают (K4, M11).
- **Миграции Room v2→v10.** Только автоматические и аддитивные; удаление колонки в v7 — по ADR-0017. Каждый шаг покрыт `MigrationTest`. Ключи DataStore не изменились, кроме перехода со старого `background_opacity` (K5, M12, M19).
- **Конвенции AGENTS.md.**
  - Нет Material, TextField на экране поиска и `!!` в основном коде.
  - Все кнопки-значки идут через `GlyphButton`.
  - `@Suppress` для detekt нет; detekt — 0 находок.
  - `MainActivity` осталась тонкой, логика разложена по держателям состояния (M13, C4).
- **Переводы.** Полные во всех 7 локалях (M15).
- **Прочее (M17, M18, M20):**
  - восстановление стека настроек устойчиво к испорченному состоянию;
  - рефлексия только в разрешённом месте D.13;
  - счётчик уведомлений не читает текст уведомлений.

## Находки и решения

| # | Находка | Серьёзность | Решение |
|---|---|---|---|
| C1 | В 0.3.0 из поиска убрана кнопка «Очистить историю спейса». После этого стереть недавние приложения (`search_recent`) в приложении было нельзя: «Очистить использование» их намеренно оставляло | Low (контроль пользователя над данными) | **Исправлено.** `clearUsage` в той же транзакции удаляет и недавние всех спейсов. Пункт переименован в «Стереть историю запусков», подтверждение перечисляет, что удаляется (7 языков). Добавлен тест |
| C2 / M6 | Политика писала «история запусков из поиска, только для сортировки результатов». На деле история пишется при любом запуске и питает поиск, недавние и подсказки «?». Не были названы дни запусков по спейсам, время последней подсказки, снимок главного экрана и журнал завершений процесса | Low (точность политики) | **Исправлено.** `privacy-policy.md` (RU и EN, вступает в силу 2026-10-18) перечисляет всё, что хранится, и путь к стиранию. Ответы `data-safety.md` верны без изменений: данные не передаются |
| M5 | Текст приватности в приложении не упоминал фоновые изображения | Low | **Исправлено** во всех 7 локалях |
| M3 | Если на устройстве нет ни экрана доступа к уведомлениям для приложения, ни общего экрана, запасной `startActivity` не был защищён, и приложение падало | Low (устойчивость) | **Исправлено.** Второй `try/catch` показывает сообщение |
| M2 | `HomeSnapshotStore.read` выделял список по числу строк из файла без ограничения | Low (устойчивость) | **Исправлено.** Число строк проверяется (0..512) до выделения; иначе снимок игнорируется. Добавлен тест. Длина строк ограничена форматом `readUTF` (до 64 КБ) |
| C3 | Выпадающие списки настроек затемняют и размывают фон флагами окна попапа через `WindowManager.LayoutParams`. Muse: это публичный API, а не внутренности Compose (OVERSTATED) | Info | **Гигиена.** При закрытии флаги снимаются, если окно ещё живо; поведение не изменилось |
| M1 | `IconDiskCache.read` якобы выделяет память по размеру из файла без проверки | — | **Не принято.** Массив выделяется только когда размер из файла равен ожидаемому `key.sizePx`, иначе `null`. Совпадение испорченного 0 с маркером буквы даёт значок-букву, а не ошибку. Кэш лежит в приватном `cacheDir` |
| M4 | `SpaceBackgroundStore.copy` не проверяет, что копирует картинку | Info | Принято как есть: вызывается только с приватным старым файлом фона при переходе на фоны по спейсам |
| M7 | Битмап, декодированный после ухода из настроек, отбрасывается без `recycle()` | Info | Принято как есть: пиксели освобождает сборщик мусора |
| M8 | Канал эффектов `Channel(UNLIMITED)` | Info | Принято как есть: события порождают только действия пользователя, их читают в состоянии STARTED |
| M9 | Экспортированная ASSIST-активность открывает поиск лаунчера по интенту любого приложения | Info | Принято как есть: так задумано, открывается только интерфейс, данные не выдаются |
| M14 | Оставшиеся предупреждения lint стилевые: `LockedOrientationActivity`, `UseKtx`, `PluralsCandidate`, `ModifierParameter`, версия AGP | Info | Принято как есть |
| M16 | Без unit-теста остался только `ExitLog` | Info | Принято как есть: класс в `:app` и пишет только служебный журнал |

## Уточнения к находкам Claude по проверке Muse
- K2: «ui-tooling нет в release» верно для `ui-tooling`. Аннотации `ui-tooling-preview` в release есть, они безвредны.
- K4: формулировка «чтение с проверкой границ» была неточной. Это и привело к исправлению M2.
- C2: `data-safety.md` править не нужно.
