# Аудит безопасности перед публикацией на GitHub

Дата: 2026-10-15, коммит f9b8a85. Цель — публичный репозиторий `github.com/mushinlab/mushin-launcher` (сейчас пустой).

Два вопроса:
1. Что попадёт в публичный доступ: секреты, ключи, персональные данные — в дереве и в истории git.
2. Можно ли, зная исходный код, навредить пользователю установленного приложения.

Прошлое ревью — [security-review.md](security-review.md) (2026-10-04). Здесь проверено заново всё, плюс код, добавленный после него.

## Что проверено
- Все 247 файлов дерева и все 28 коммитов истории (`git log -p --all`): шаблоны ключей AWS/GitHub/Google/OpenAI/Slack, приватные ключи PEM, `storePassword`/`keyPassword` со значениями, токены. Удалённых из истории файлов, кроме одного `.kt`, нет.
- Персональные данные: пути `/Users/…`, e-mail, телефоны, серийный номер телефона владельца, метаданные PNG (tEXt/iTXt/eXIf) и `Mushin-Launcher.docx`, отпечатки устройств в `perf/results/*.json`.
- `gradle-wrapper.jar`: SHA-256 `7a9ce74c…262c5d` совпадает с services.gradle.org; дистрибутив закреплён `distributionSha256Sum`, сумма совпадает.
- Манифест, экспортированные компоненты, обработка intent, PendingIntent, приёмники, файлы, декодирование изображений, рефлексия, логи, CI.

## Модель угроз «злоумышленник знает исходный код»
Проверено и в порядке:
- **Нет поверхности для удалённой атаки.** Нет `INTERNET`, сетевого кода, WebView, загрузки кода (`DexClassLoader`, `Runtime.exec`). `:app:checkReleasePermissions` ломает сборку при появлении `INTERNET`/`QUERY_ALL_PACKAGES`.
- **Экспортированные компоненты.** `MainActivity` (HOME/INFO/ASSIST) читает только action и category. Слушатель уведомлений защищён `BIND_NOTIFICATION_LISTENER_SERVICE`, плитка — `BIND_QUICK_SETTINGS_TILE`. `InitializationProvider` не экспортирован. Динамические приёмники `RECEIVER_NOT_EXPORTED`. `taskAffinity=""` защищает от перехвата задачи.
- **Запуск приложений.** Только компоненты из каталога `LauncherApps`; удаление — через системное подтверждение. `Intent.parseUri` и intent из хранилища нет.
- **Данные.** Всё во внутреннем хранилище, Room-запросы параметризованы, бэкап и перенос исключены правилами. Из уведомлений читаются только пакет, пользователь и флаги.
- **Фон из галереи.** Выбор через системный Photo Picker; `ImageDecoder` уменьшает до размера экрана, программный аллокатор, ошибки и OOM пойманы `runCatching`.
- **Подделка приложения.** Собрать клон из исходников может любой, но поверх установленной версии Android его не поставит: подпись не совпадает. Защита — ключ подписи вне репозитория (уже так), Play App Signing и публикация SHA-256 сертификата подписи рядом с релизами.
- **CI.** Секретов в workflow нет, токен только `contents: read`, триггер `pull_request` (не `pull_request_target`) — PR из форков ничего не получат. `setup-gradle@v4` сам проверяет wrapper.

## Независимая проверка (Muse)
Второй аудитор (Muse, через оркестрацию Orca) сначала провёл свой аудит, не видя этого файла, затем проверил каждую находку.

- **Совпало:** P1 (Muse оценил как High), P2, A1, A2, A4, а также `profileable` (принят ранее, Q-77). P3, P4, A3, A5, A6 Muse подтвердил при проверке. Опровергнутых находок нет.
- **Только у Muse**, рассмотрены и не приняты как проблемы безопасности:
  - M7 — `IconLoader.readDisk` не ограничивает размер из файла кэша. Файл лежит в приватном `cacheDir`, и посторонний его не изменит. Ошибку и OOM ловит `runCatching`, а вместо иконки показывается буква.
  - M8 — нет жёсткого предела размера фона. `setTargetSize` задаётся в обработчике заголовка, до декодирования пикселей, поэтому память ограничена размером экрана. Файл выбирает сам пользователь через Photo Picker.
  - M9 (рефлексия шторки, исключение D.13) и M10 (клон под другим именем) — принятые риски.
- **Расхождения в фактах:**
  - Muse счёл неточным номер строки в P2. Ссылка действительно на `docs/adr/README.md:20`.
  - Muse не смог без сети сверить сумму дистрибутива Gradle. Её проверил Claude: `acd53f1e…` совпадает с services.gradle.org.

## Что сделано
1. P1 — автор и коммиттер всех коммитов переписаны на адрес GitHub noreply, локальный `user.email` — тот же адрес.
2. P2 — ссылка на артефакт убрана из `docs/adr/README.md`.
3. A1 — без `keystore.properties` release собирается **неподписанным**, его нельзя установить или загрузить. Debug-подпись — только явно: `-Penv.debugSignedRelease=true`. Варианты `benchmarkRelease`/`nonMinifiedRelease` плагин Baseline Profile по-прежнему подписывает debug-ключом, замеры работают.
4. A2 — actions закреплены по SHA.
5. A5 — обновлён `security-review.md`.
6. P3 — в GitHub отправляется только `main`.

Отложено: A3 (`verification-metadata.xml`). Оба аудитора считают, что это можно сделать позже.

Владельцу после публикации (в интерфейсе GitHub), A6:
- защита ветки `main`;
- secret scanning и push protection;
- Dependabot alerts;
- private vulnerability reporting;
- «Keep my email addresses private» и «Block command line pushes that expose my email»;
- SHA-256 сертификата подписи рядом с релизами.
