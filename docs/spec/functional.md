# B. Функциональная спецификация

Общие правила для всех критериев приёмки:

- «Кадр» — один vsync на устройстве.
- Все размеры — в dp/sp на Pixel 6 (1080 px ширины, density 2,625, ширина 411 dp).
- «Компонент» — пара `(ComponentName, UserHandle)`; в БД UserHandle хранится как `user_serial = UserManager.getSerialNumberForUser()`.

## F01. Роль HOME и онбординг

**US-01.** Как владелец, я хочу при первом запуске сделать «Энв» лаунчером по умолчанию, чтобы кнопка Home вела в него.

- **AC-01.1.** Given приложение установлено и роль `ROLE_HOME` не принадлежит ему, When открыта MainActivity, Then над часами показывается карточка «Сделать лаунчером по умолчанию» (высота 56dp, цвет `accent`). Тап по ней вызывает `RoleManager.createRequestRoleIntent(ROLE_HOME)` через ActivityResult API.
- **AC-01.2.** Given пользователь подтвердил роль, When вернулся результат `RESULT_OK`, Then карточка исчезает в том же кадре и больше не показывается.
- **AC-01.3.** Given пользователь отказал, When вернулся результат, Then карточка остаётся; повторный запрос — только по тапу.
- **Edge.** Роль отозвали в системных настройках → при `onResume` проверка `isRoleHeld` и снова карточка. Без роли Private Space недоступен (F16 скрыт).

## F02. Каталог приложений

**US-02.** Как владелец, я хочу, чтобы лаунчер всегда знал актуальный список приложений всех профилей и не требовал перезапуска.

- **AC-02.1.** Given старт процесса, When `AppCatalog.load()`, Then для каждого `UserHandle` из `LauncherApps.getProfiles()` вызывается `getActivityList(null, user)`. Результат кладётся в неизменяемый `List<AppEntry>`, данные выдаются через `StateFlow`.
- **AC-02.2.** Given установлено новое приложение, When приходит `LauncherApps.Callback.onPackageAdded`, Then оно появляется в поиске не позже чем через 500 мс без перезапуска.
- **AC-02.3.** Given приложение удалено (не replacing), When приходит `onPackageRemoved`, Then применяется Q12; строка исчезает с главного экрана в том же обновлении состояния.
- **AC-02.4.** Given приложение обновлено, When приходит `onPackageChanged`, Then инвалидируются кэш иконки и метка.
- **AC-02.5.** Given рабочий профиль на паузе (`isQuietModeEnabled == true`), Then его приложения в списках показываются с альфой 0,5. Тап по такому приложению вызывает `UserManager.requestQuietModeEnabled(false, user)`.
- **AC-02.6.** Given у пакета несколько launcher-activity, Then каждая — отдельный компонент.
- **Edge.** Приложение suspended (`onPackagesSuspended`) → альфа 0,5; при тапе `startMainActivity` может выбросить исключение → тост «Приложение приостановлено». Приложение без метки → используется packageName. Дубликаты меток в разных профилях различаются значком портфеля (C.6).
- **Ошибки.** `SecurityException` / `ActivityNotFoundException` при запуске → тост «Не удалось открыть» и предложение «Убрать из энва».

## F03. Главный экран

**US-03.** Как владелец, я хочу видеть крупное время, дату и текстовый список избранного текущего энва с явными тап-зонами, чтобы запускать приложения без промахов.

- **AC-03.1.** Given главный экран, Then сверху вниз идут:
  - верхний инсет статус-бара + 40dp;
  - часы `HH:mm` (или `h:mm` в 12-часовом режиме) — 72sp, вес 300, `textPrimary`;
  - отступ 4dp, дата в формате `EEEE, d MMMM` по локали — 18sp, `textSecondary`;
  - отступ 32dp, список.
- **AC-03.2.** Каждая строка:
  - высота 64dp, ширина на весь экран (от 0 до 411dp, без боковых полей у фона);
  - фон чередуется: чётные — `zebraA`, нечётные — `zebraB`;
  - текст 26sp, вес 400, одна строка, ellipsis в конце, горизонтальные отступы 24dp;
  - тап-зона — вся строка.
- **AC-03.3.** Given тап по строке, When UP в пределах строки и смещение < touchSlop, Then `LauncherApps.startMainActivity()` вызывается в обработчике UP, без задержки на распознавание двойного тапа.
- **AC-03.4.** Given изменилось время (`ACTION_TIME_TICK`, `ACTION_TIME_CHANGED`, `ACTION_TIMEZONE_CHANGED`), Then часы обновляются в ближайшем кадре. Перекомпонуется только composable часов: состояние минуты лежит в отдельном `State`.
- **AC-03.5.** Given выбран формат «Системный», Then используется `DateFormat.is24HourFormat(context)`.
- **AC-03.6.** Колокольчика (уведомлений) и нижней области режима Work **нет**.
- **AC-03.7.** Given в энве 0 элементов, Then вместо списка показывается одна строка `textSecondary` 16sp: «Долгое нажатие → ⚙ → Энвы, чтобы добавить приложения».
- **Edge.** fontScale 2,0 → высота строки = max(64dp, высота текста + 16dp), количество строк пересчитывается. Если элементов больше, чем помещается (например, после увеличения шрифта), лишние не рендерятся, а в редакторе показывается предупреждение.

## F04. Иконки

**US-04.** Как владелец, я хочу видеть иконку слева, справа или не видеть её вовсе, причём иконка всегда монохромная в цвете палитры.

- **AC-04.1.** Настройка `icon_mode ∈ {NONE, LEFT, RIGHT}`, по умолчанию LEFT (ADR-0022; было NONE).
  - Размер иконки на главном экране 28dp, отступ от текста 16dp, вертикально по центру строки.
  - При RIGHT иконка прижата к правому отступу 24dp, текст остаётся выровненным влево.
- **AC-04.2.** Given у иконки есть `AdaptiveIconDrawable.getMonochrome() != null`, Then рисуется монохромный слой, окрашенный в `iconTint`.
- **AC-04.3.** Given монохромного слоя нет, Then иконка (adaptive с маской или legacy) растеризуется, обесцвечивается (`ColorMatrix.setSaturation(0)`) и окрашивается по алгоритму D.7.
- **AC-04.4.** Given иконка уже в кэше (память или диск), Then отображение не блокирует кадр. Если иконки ещё нет, место под неё резервируется пустым (без плейсхолдера), иконка появляется в следующем кадре после загрузки.
- **AC-04.5.** Given смена палитры, Then иконки перекрашиваются без перерастеризации: окрашивание делается через `ColorFilter` при отрисовке.
- **Edge.** Иконка, которая после обработки получилась полностью непрозрачной (белый квадрат): если покрытие маски > 92 %, вместо неё рисуется первая буква метки 18sp в круге 28dp с обводкой 1,5dp `iconTint`.

## F05. Энвы

**US-05.** Как владелец, я хочу переключать контекст (обычный, работа, свой), чтобы менялись палитра, набор и порядок избранного и история поиска.

- **AC-05.1.** При первом запуске создаются «Обычный» (NORMAL, палитра `Graphite`) и «Работа» (WORK, палитра `Navy`); текущим становится «Обычный».
- **AC-05.2.** Given переключение энва, Then в том же кадре меняются палитра, список избранного, recents и стиль системных баров. Анимаций нет.
- **AC-05.3.** У каждого энва свои `environment_item` и `search_recent`.
- **AC-05.4.** NORMAL удалить нельзя (пункт неактивен). WORK можно удалить и создать заново (не более одного). CUSTOM — от 0 до 20.
- **AC-05.5.** Удаление энва требует подтверждения в диалоге «Удалить энв "X"? Избранное и история энва будут удалены». Если удалён текущий энв, текущим становится NORMAL.
- **AC-05.6.** Имя: 1–24 символа после trim, уникальное без учёта регистра.

## F06. Long-press popup

**US-06.** Как владелец, я хочу долгим нажатием в любом месте главного экрана открыть панель под пальцем, чтобы переключить энв или открыть настройки.

- **AC-06.1.** Given палец неподвижен (смещение < touchSlop) дольше `viewConfiguration.longPressTimeoutMillis`, Then:
  - в том же кадре popup появляется под точкой касания;
  - срабатывает `HapticFeedbackConstants.LONG_PRESS`;
  - дальнейшее движение пальца не запускает свайп-жест.
- **AC-06.2.** Состав popup на фоне: список энвов (у текущего — ✓ и жирное начертание), divider 1dp `divider`, строка «⚙ Настройки».
- **AC-06.3.** Состав popup на строке приложения: заголовок с меткой приложения (14sp `textSecondary`, 40dp), «Об приложении», «Переименовать», «Скрыть», «Убрать из энва», «Удалить», divider, энвы, divider, «⚙ Настройки». «Удалить» скрыт для системных приложений (`ApplicationInfo.FLAG_SYSTEM` без `FLAG_UPDATED_SYSTEM_APP`).
- **AC-06.4.** Позиционирование описано в D.10. Popup никогда не выходит за safe-area (инсеты статус-бара, навбара и выреза плюс 8dp).
- **AC-06.5.** Popup закрывается тапом вне его, Back, Home, выбором пункта.
- **AC-06.6.** Выбор энва переключает его (F05) и закрывает popup в том же кадре.
- **Edge.** Long-press во время открытого поиска не обрабатывается. Второй палец во время ожидания long-press отменяет его.

## F07. Двойной тап → поиск

**US-07.** Как владелец, я хочу двойным тапом по экрану мгновенно получить поиск с клавиатурой.

- **AC-07.1.** Given два DOWN на фоне (не на строке) с интервалом ≤ `doubleTapTimeoutMillis` (системное значение; в AOSP `DOUBLE_TAP_TIMEOUT = 300` мс) и расстоянием ≤ 100dp, When пришёл **второй DOWN**, Then в ближайшем кадре видны поиск и клавиатура: пустой запрос, активная раскладка — последняя использованная.
- **AC-07.2.** Первый тап на фоне ничего не делает, поэтому задержка ожидания второго тапа не видна пользователю.
- **AC-07.3.** Системный IME не появляется никогда: поиск не содержит `TextField` и `BasicTextField`, и ни один его элемент не получает фокус ввода.
- **AC-07.4.** Тап по строке избранного запускает приложение сразу (AC-03.3). Двойной тап по строке не распознаётся: первый тап уже запустил приложение.

## F08. Встроенная клавиатура

**US-08.** Как владелец, я хочу собственную клавиатуру лаунчера: только буквы, цифры скрыты под верхним рядом, раскладки переключаются.

- **AC-08.1.** Раскладки (минимум): EN QWERTY, RU ЙЦУКЕН (D.12); с ADR-0023 также ES, PT, DE, FR, ID. Порядок и включённость задаются в настройках «Клавиатура» (список с «Убрать» и «Добавить ещё», ADR-0023). Должна быть включена хотя бы одна.
- **AC-08.2.** Нажатие:
  - на DOWN — подсветка клавиши (`keyPressed`) и `HapticFeedbackConstants.KEYBOARD_TAP`, если haptics включены;
  - на UP — ввод буквы.
- **AC-08.3.** Цифры висят на клавишах верхнего ряда: EN `q..p` → `1..0`, RU `й..з` → `1..0`; у «х» и «ъ» цифр нет. Цифра вводится, если:
  - палец ушёл вверх от точки DOWN на ≥ 24dp, или
  - удержание дольше 300 мс (показывается подсказка-«пузырь» 48×56dp над клавишей; ввод на UP).

  Маленькая подсказка цифры (10sp, `textSecondary`) всегда видна в правом верхнем углу клавиши.
- **AC-08.4.** Backspace: тап удаляет 1 символ. Удержание: первый повтор через 400 мс, далее каждые 50 мс. Свайп влево по backspace на ≥ 48dp очищает весь запрос.
- **AC-08.5.** Клавиша языка переключает раскладку по кругу. Подпись — код следующей раскладки («RU»/«EN»). Смена мгновенная.
- **AC-08.6.** Enter запускает результат №1 (Q3).
- **AC-08.7.** Появление и скрытие без анимации.
- **AC-08.8.** Мультитач: второй палец, пока первый на другой клавише, вводит первую букву на DOWN второго пальца (rollover).
- **Edge.** Запрос длиннее 32 символов → дальнейший ввод игнорируется, haptic REJECT.

## F09. Поиск

**US-09.** Как владелец, я хочу находить приложение по началу слова, по части слова, по инициалам, с опечаткой, в неправильной раскладке, транслитом и по своему переименованию.

- **AC-09.1.** Перерасчёт результатов после каждого символа укладывается в ≤ 4 мс (P95) для 500 приложений на Pixel 6. Измерение — microbenchmark модуля `:core:search`.
- **AC-09.2.** Обязательные кейсы (unit-тесты, таблица в D.11):
  - «sl» → Slack №1;
  - «ыдфсл» → Slack №1;
  - «слак» → Slack в топ-3;
  - «gm» → Google Maps в топ-3;
  - «tlgrm» → Telegram в топ-3;
  - «телеграм» → Telegram №1;
  - «sber» → «СберБанк» №1;
  - «ckfr» → Slack в топ-3;
  - переименованный «Почта» (Gmail) находится по «поч» и по «gm».
- **AC-09.3.** Пустой запрос: слева — все видимые (не скрытые) приложения по алфавиту, через `LazyColumn` со скроллом; справа — recents.
- **AC-09.4.** Скрытые приложения (`hidden = 1`) не показываются при пустом запросе. При непустом показываются, только если совпадение уровня EXACT или PREFIX, с суффиксом «(скрыто)» `textSecondary`. Так скрытое приложение остаётся доступным, но не мозолит глаза.
- **AC-09.5.** Тап по результату или recent:
  - приложение запускается;
  - в `search_recent` текущего энва записывается `(component, now)`, в `app_usage` — `count+1, last=now`;
  - поиск закрывается и сбрасывается после запуска (ко времени возврата на Home виден главный экран).
- **AC-09.6.** Результатов нет → в левой панели строка «Ничего не найдено» (16sp `textSecondary`).

## F10. Recents

**US-10.** Как владелец, я хочу справа видеть недавно запущенные из поиска приложения текущего энва, кроме тех, что уже есть на его главном экране.

- **AC-10.1.** Ширина панели — `floor(screenWidth / 3)`, около 137dp; результаты — остаток (около 274dp). Между ними вертикальный divider 1dp.
- **AC-10.2.** Содержимое — `search_recent` текущего энва, по `last_launched_at DESC`. Исключаются компоненты из `environment_item` этого энва, скрытые и удалённые. Показываются до 10 записей или сколько помещается по высоте.
- **AC-10.3.** Записи появляются только от запусков **из поиска**: результат, recent или Enter. Запуски с главного экрана и жестами туда не попадают.
- **AC-10.4.** Строка: 52dp, текст 16sp, ellipsis, фон-зебра. Иконка — по `icon_mode`, размер 20dp.
- **AC-10.5.** «Очистить историю энва» — в Настройки → Поиск, с подтверждением.
- **Хранение.** До 50 записей на энв, старые удаляются при вставке.

## F11. Настройки, редактор энва, скрытие и переименование

**US-11a.** Как владелец, я хочу добавлять, удалять и переупорядочивать избранное энва перетаскиванием.

- **AC-11.1.** В редакторе энва — список текущих элементов. У каждого: drag-handle 48×48dp справа и кнопка «−» 48×48dp слева.
  - Перетаскивание: long-press на handle (≥ 200 мс) → строка поднимается (`elevation` 0; выделение фоном `accent` с альфой 12 %) → перемещение → отпускание. Порядок сохраняется в Room одной транзакцией.
  - Доступный дубль: у каждой строки пункты меню «Вверх» и «Вниз».
- **AC-11.2.** «+ Добавить» открывает пикер приложений: поиск системным `TextField` (здесь он разрешён, Q10), мультивыбор, «Готово». Уже добавленные помечены ✓. Лимит — Q4.
- **AC-11.3.** Палитра энва: выбор из пресетов (C.5). В v1.1 добавляется «Своя» с HEX по ролям.

**US-11b.** Как владелец, я хочу переименовать или скрыть приложение глобально.

- **AC-11.4.** «Переименовать»: диалог с `TextField`, 1–40 символов; пустое значение означает «сбросить». Новое имя применяется везде: на главном экране, в поиске (D.11 индексирует и исходное, и новое имя), в recents.
- **AC-11.5.** «Скрыть» исключает приложение из списка «все приложения» (пустой запрос) и из пикеров. Из избранного оно не удаляется, но в редакторе помечается «скрыто». Список скрытых — Настройки → Приложения, там же «Показать».

## F12. Жесты свайпа

**US-12.** Как владелец, я хочу назначить свайпам вверх, вниз, влево и вправо действие или приложение.

- **AC-12.1.** Действия: `NONE`, `LAUNCH_APP(component)`, `NOTIFICATIONS`, `SEARCH` (как двойной тап), `ALL_APPS` (поиск в режиме просмотра). По умолчанию: UP = SEARCH, DOWN = NOTIFICATIONS, LEFT = NONE, RIGHT = NONE.
- **AC-12.2.** Распознавание и пороги — C.4 и D.9.
- **AC-12.3.** NOTIFICATIONS вызывает `expandNotificationsPanel` через рефлексию. Given вызов выбросил исключение, Then показывается один тост за сессию: «Шторка недоступна на этой версии Android».
- **AC-12.4.** Given назначенное приложение удалено, Then биндинг сбрасывается в NONE, а в настройках жестов показывается «(приложение удалено)».

## F13. Home и Back

- **AC-13.1.** Given открыт поиск, popup или настройки, When нажат Home (приходит `onNewIntent` с `CATEGORY_HOME`, пока Activity в `RESUMED`), Then всё закрывается и показывается главный экран текущего энва в том же кадре.
- **AC-13.2.** Given главный экран без оверлеев, When нажат Home, Then ничего не происходит.
- **AC-13.3.** Back — через `BackHandler`. Порядок закрытия: popup → поиск → экран настроек (стек) → главный экран. На чистом главном экране callback включён и ничего не делает (лаунчер не закрывается).
- **AC-13.4.** Given пользователь вернулся из приложения жестом «домой», Then поиск уже закрыт и сброшен (AC-09.5), popup закрыт.

## F14. Аппаратная клавиатура

- **AC-14.1.** Given главный экран и подключена физическая клавиатура, When нажата клавиша с буквой, Then открывается поиск, буква становится первым символом запроса, экранная клавиатура скрыта, пока используется аппаратная.
- **AC-14.2.** Клавиши внутри поиска: Backspace, Enter (запуск №1), Escape (закрыть), стрелки вверх и вниз (выделение результата; Enter запускает выделенный), Ctrl+Space (смена раскладки).
- **Реализация.** `Activity.dispatchKeyEvent` → `KeyboardRouter`; символ — через `KeyEvent.getUnicodeChar(metaState)`. Если пришла кириллица, она принимается как есть, если латиница — тоже как есть (аппаратная раскладка системная).
