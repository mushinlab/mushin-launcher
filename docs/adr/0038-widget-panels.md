# ADR-0038. Две панели виджетов, пустая панель без высоты, системный выбор

Статус: принято (указание владельца; конкретные размеры и компоновка — реализация агента). 2026-11-07. Завершает предложение виджетов ADR-0037; отменяет исключение F26 исходного spec. Дополняет ADR-0036.

## Контекст
Владелец уточнил: «Две панели. Но нужно учитывать что в одной из них не будет ничего или в двух сразу, так они не должны занимать место… это размер панели, да, по высоте… панель же системная будет с виджетами?».

## Решения
1. У каждого спейса две независимые панели: над списком и под списком. Изначально есть только встроенное время в верхней панели. Внешние виджеты добавляются пользователем из установленных приложений.
2. Пустая панель имеет нулевую высоту. Если обе пусты, обе схлопываются. В режиме редактирования в каждом месте остаётся только компактная кнопка «Добавить виджет +» высотой 48 dp.
3. Кнопка управления виджетами находится справа от палитры. Её минимодалка содержит верхнюю и нижнюю панели: высота, список виджетов, удаление и добавление. Время ведёт в существующие настройки часов. Удаление встроенного времени убирает его из текущего спейса; его прежние параметры не стираются.
4. Small / Medium / Large задаёт высоту панели, а не отдельного виджета. Реализация: 120 / 200 / 280 dp. Соседние виджеты располагаются горизонтально; панель листается. Ширина внешнего виджета определяется соотношением его минимальных размеров и ограничена шириной экрана; доступная геометрия передаётся провайдеру через `updateAppWidgetSize`. Если минимальный размер виджета больше места в панели, его содержимое измеряется не меньше этого минимума и целиком масштабируется в панель. Если обе крупные панели не оставляют двух строк списка и кнопок редактирования, их высоты пропорционально ограничиваются доступным экраном. Список приложений прокручивается, сохранённые строки не отрезаются.
5. Выбор — штатный `AppWidgetManager.ACTION_APPWIDGET_PICK`. Встроенное время добавлено в него через `EXTRA_CUSTOM_INFO` и `EXTRA_CUSTOM_EXTRAS`. Оформление и наличие превью зависят от системной реализации; собственная панель Pixel Launcher не является общедоступным системным API. Доступные внешние варианты и их метаданные задаёт приложение-провайдер.
6. Android-виджеты размещает `AppWidgetHost` с постоянным host id. Если провайдеру нужна настройка, запускается штатная конфигурация через host, в том числе для другого профиля. Нажатия внутри виджетов получает их `AppWidgetHostView`; слой жестов лаунчера их не перехватывает.
7. Панели спейсов и незавершённый запрос выбора/конфигурации хранятся в отдельном локальном DataStore `widgets`; существующие Room-таблицы и ключи не меняются, новых зависимостей и разрешений нет. Отмена и ошибка освобождают выделенный widget id. При старте освобождаются бесхозные id; удаление спейса или приложения очищает соответствующие записи и экземпляры.
8. Снимок главного экрана v6 содержит раскладку панелей. Версии 3–5 читаются с прежним временем сверху. Возвращение из выбора и Back сохраняют режим редактирования.

## Проверки
- Unit: независимые раскладки спейсов и высоты, восстановление незавершённого запроса после открытия файла, повреждённые данные, геометрия пустых и крупных панелей, снимок главного экрана.
- UI API 36: обе пустые панели, управление высотой, встроенное время через системный выбор, реальный виджет установленного приложения, удаление, отмена без утечки id, прокрутка и запуск приложения при нехватке места.
