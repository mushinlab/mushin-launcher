# ADR-0051. Сетка виджетов 8×8 и максимум четыре виджета

Статус: принято по указанию владельца, 2026-11-21. Заменяет решение 1 и формат из решения 7 ADR-0040 (сетка 2×2, формат v4); остальные решения ADR-0040 и ADR-0044 действуют.

## Контекст
Владелец: плашка с виджетами должна быть гибче — шаг не 2×2, а 8×8, но виджетов по-прежнему не больше четырёх; если нижние клетки не заняты, список приложений подъезжает к последней занятой строке. Сейчас сетка фиксированно 2 колонки × 2 строки, каждый виджет занимает четверть, пустые крупные строки скрываются.

## Решения
1. Панель — одна сетка 8 колонок × 8 строк мелких клеток. Высота панели прежняя (два ряда по 112dp и зазор), поэтому мелкая клетка — около 1/8 ширины и 1/8 высоты панели. Виджет занимает прямоугольник из мелких клеток без пересечений.
2. Лимит — не больше четырёх виджетов вместе с часами. Пятый не добавляется: `WidgetLayout.add` возвращает null, выбор виджетов не открывается, ячеек добавления нет.
3. Размер Android-виджета по-прежнему задаётся его минимальными размерами с системными полями, округлёнными вверх до мелких клеток; масштабирования нет. Провайдер, который не помещается в 8×8, в выборе не показывается (ADR-0044).
4. Вне редактирования место занимают только мелкие строки до последней занятой включительно: панель сжимается до нижней занятой клетки, список избранного подъезжает вплотную. Пустая часть занятой строки по горизонтали место занимает.
5. В редактировании видны все восемь строк. Ячейка «Добавить виджет» — свободная четверть панели (4×4 мелкие клетки). Если свободной четверти нет, но виджет ещё можно добавить, показывается одна компактная ячейка с плюсом в первой свободной мелкой клетке.
6. Перенос, растягивание и ручки привязаны к мелким клеткам. Правила вытеснения и замены не меняются (ADR-0040, решения 3–6).
7. Формат виджетов v5 хранит мелкие координаты. v4 читается умножением колонки, строки, размеров и целевой ячейки ожидающей привязки на 4. v1–v3 раскладываются по четвертям в прежнем порядке: стандартная колонка остаётся колонкой. Встроенные часы по умолчанию занимают левую верхнюю четверть.
8. Новых зависимостей и разрешений нет.

## Вопросы, решённые без владельца
| № | Вопрос | Решение |
|---|---|---|
| Q-188 | Достаточно ли шага 1/8? | Да: владелец назвал 8×8 как пример, шаг 1/8 укладывается в прежнюю высоту панели |
| Q-189 | Как выглядят ячейки добавления в мелкой сетке? | Свободными четвертями, иначе одной компактной ячейкой: 64 подписи «Добавить виджет» не помещаются |
| Q-190 | Часы входят в лимит четырёх? | Да, как раньше: часы — такая же плитка панели |
| Q-191 | Подъезжает ли список, если занята только часть нижней строки? | Нет: скрываются только целиком пустые мелкие строки |

## Проверки
- **AC-51.1.** Given панель, Then это сетка 8×8; виджетов вместе с часами не больше четырёх; попытка добавить пятого не меняет панель и не открывает выбор.
- **AC-51.2.** Given редактирование, When перенос или растягивание, Then прямоугольник привязан к мелким клеткам; ячейки добавления — свободные четверти, а без свободной четверти — одна компактная ячейка с плюсом.
- **AC-51.3.** Given главный экран вне редактирования, Then пустые нижние мелкие строки не занимают места, и список избранного стоит вплотную под последней занятой строкой.
- **AC-51.4.** Given сохранённый формат v4, Then координаты умножаются на 4, часы и виджеты остаются на своих четвертях.
- **AC-51.5.** Given провайдер, у которого минимальный размер с полями не помещается в 8×8, Then он не предлагается; помещающийся занимает наименьший прямоугольник мелких клеток.

Unit: координаты, лимит четырёх, добавление с вытеснением, миграция v4 и v1–v3, ячейки добавления, видимые мелкие строки. UI API 36: добавление в свободную четверть, перенос и растягивание с мелким шагом, полная панель без ячеек добавления, подъезд списка, перезапуск. Визуальный просмотр в эмуляторе.
