# ADR-0044. Выбор виджетов: видимость провайдеров и виджеты больше ячейки

Статус: принято по указанию владельца, 2026-11-15. Изменяет AC-39.3. Заменяет решение 4 ADR-0039 в части «помещается в ячейку»; остальное в ADR-0039 и ADR-0040 действует. Выпущено в 0.10.0.

## Контекст
Владелец не увидел в выборе виджеты своего телефона Xiaomi и попросил проверить поддержку виджетов. Проверка на эмуляторе API 36 (31 провайдер в системе) нашла две причины:
- Видимость пакетов. `AppWidgetManager.getInstalledProviders` отдаёт только провайдеры пакетов, видимых приложению. В манифесте был один запрос — `MAIN/LAUNCHER`, поэтому виджеты пакетов без иконки запуска не попадали в список. На эмуляторе так пропадал «Battery» из `com.google.android.settings.intelligence`; на прошивках производителей системные виджеты часто живут именно в таких пакетах.
- Отбор по размеру. С ADR-0039 выбор показывал только провайдеры, минимальный размер которых помещается в одну ячейку (половина ширины × 112dp). После ADR-0040 виджет может занимать до 2×2 ячеек, но отбор остался прежним: на эмуляторе он прятал 16 провайдеров из 31, из них 15 помещаются в сетку.

## Решения
1. В `<queries>` манифеста добавлен запрос по действию `android.appwidget.action.APPWIDGET_UPDATE`. Приложение видит пакеты, у которых есть провайдер виджетов. `QUERY_ALL_PACKAGES` по-прежнему не используется, новых разрешений нет.
2. Выбор показывает провайдеры, минимальный размер которых с системными полями помещается в сетку 2×2. Как и раньше, по оси с разрешённым изменением берётся `minResize`, иначе `min`; масштабирования нет.
3. Для провайдера считается нужное число ячеек по каждой оси (1 или 2). При добавлении виджет занимает свободный прямоугольник этого размера: сначала тот, в который входит выбранная ячейка, затем любой свободный. Если свободного нет, накрытые виджеты переезжают по правилам ADR-0040 (п. 5).
4. Если места на полный размер нет, виджет сохраняет ширину в одной строке, затем высоту в одной колонке, затем встаёт в одну ячейку. Добавление не отменяется.
5. Подпись в выборе: «Здесь только виджеты, которые помещаются в панель. Крупные занимают несколько ячеек.» (семь языков; строка `widgets_small_only` переименована в `widgets_fit_panel`).

## Вопросы, решённые без владельца
| № | Вопрос | Решение |
|---|---|---|
| Q-160 | Чем расширить видимость пакетов? | Запросом по `APPWIDGET_UPDATE`: открывает только пакеты с виджетами, без `QUERY_ALL_PACKAGES` |
| Q-161 | С каким размером добавлять крупный виджет? | С минимальным допустимым, а не с размером по умолчанию: виджеты, помещавшиеся в ячейку, ведут себя как раньше |
| Q-162 | Что делать, если на нужный размер нет места? | Ставить в меньший прямоугольник (п. 4), а не отказывать |
| Q-163 | Запрещать ли сжимать крупный виджет ручками меньше его минимума? | Нет: содержимое центрируется и обрезается, как у перенесённых из старых форматов (ADR-0039, п. 6) |
| Q-164 | Показывать ли виджеты других профилей (рабочий профиль, клоны приложений)? | Нет, как и раньше: только профиль владельца |
| Q-165 | Поддерживать ли виджеты MIUI/HyperOS, которые рисует сам штатный лаунчер (MAML)? | Нет: это не виджеты Android, сторонний лаунчер получить их не может |

## Проверки
Unit: добавление широкого и высокого виджета в свободный прямоугольник, вытеснение соседа, запасные размеры без места. UI API 36: выбор содержит только помещающиеся в панель, виджет больше ячейки занимает нужные ячейки и не накрывает часы; остальные тесты виджетов без изменений (8/8). Вручную на эмуляторе: «Battery» появился после п. 1, «Chrome Dino» (110×110dp) встал в колонку на две строки. На устройстве Xiaomi не проверялось.
