# ADR-0055. Настоящая страница соседа при листании, одна кнопка добавления виджета, перенос с подрезкой высоты, выбор виджета по приложениям с превью

Статус: принято по указанию владельца, 2026-11-27. Меняет ADR-0054 (решения о размытом превью, Q-200, Q-201), ADR-0051 (ячейки добавления, AC-51.2) и ADR-0040 (перенос виджета после удержания).

## Контекст
Владелец после 0.12.0:
1. Свайп из 0.11.0 нравился больше. Выбран вариант «страница идёт за пальцем, но сосед — настоящий экран, без размытия и подмены».
2. Кнопка «Добавить виджет» должна быть одна в каждый момент.
3. Виджеты нужно перетаскивать по сетке.
4. Если высокий виджет перетащили туда, где он не помещается, при отпускании пальца он становится ниже.
5. Выбор виджета неудобный: нужна группировка по приложениям и превью виджетов.

## Решения
1. **Сосед при листании — настоящий главный экран** (`HomeScreen` с его палитрой, иконками, часами, виджетами, подсказкой и кнопками), как слайд в 0.11.0. Размытия и полос зебры больше нет. Жесты на нём выключены, его семантика скрыта: TalkBack и тесты видят только метку `space_preview_<id>`.
2. **Что готовится заранее.** Состояние обоих соседей (строки, виджеты, подсказка) и их иконки считаются в фоне при каждом изменении данных — это дёшево. Обои соседей 1080×2400 (около 10 МБ каждые) загружаются только с первым движением пальца по плашке и освобождаются после отпускания. Если обои не успели загрузиться, в первые кадры сосед виден с цветом палитры.
3. **Сдвиг только при отрисовке** у обеих страниц: координаты касаний и замер фона под часами не зависят от сдвига. Поэтому край страницы точно под пальцем, а цвет часов соседа считается так же, как после переключения.
4. **Переключение без видимой подмены.** После доезда соседняя страница стоит на месте основной, спейс переключается, и когда основной экран показывает новый спейс с его обоями, страница соседа исчезает за 100 мс. Содержимое одинаковое, поэтому растворение незаметно. Растворение и сдвиг из popup (ADR-0054, решение 5) рисуют тот же настоящий экран.
5. **Одна кнопка добавления.** В режиме редактирования — только первая свободная четверть сетки; без свободной четверти — первая свободная мелкая клетка (компактная кнопка). После добавления кнопка переезжает на следующее свободное место.
6. **Перенос без удержания.** В режиме редактирования виджет тянется сразу, после порога касания. Рамка показывает цель с привязкой к мелким клеткам; занятые виджеты, как и раньше, переезжают в свободные клетки.
7. **Подрезка высоты при переносе.** Верх виджета может встать в любую строку сетки; если виджет не помещается до нижнего края, его высота уменьшается до оставшихся строк (не меньше одной). Рамка во время переноса уже показывает итоговый размер. Ширина по-прежнему не меняется: виджет упирается в правый край.
8. **Выбор виджета.** Группы по приложениям: заголовок с иконкой и названием приложения, под ним горизонтальная лента карточек. Карточка — превью и название виджета. Превью: макет `previewLayout` (Android 12+), иначе картинка `previewImage`, иначе иконка виджета; уменьшается до 160 dp. Часы Mushin — первая группа с образцом времени. Остальные группы — по алфавиту. Превью грузятся при появлении карточки.
9. Новых зависимостей, разрешений и сетевых запросов нет. Схема БД и формат раскладки виджетов не меняются.

## Вопросы, решённые без владельца
| № | Вопрос | Решение |
|---|---|---|
| Q-202 | Держать обои соседей в памяти постоянно? | Нет: только во время свайпа. Состояние соседей считается заранее, обои — с первым движением пальца |
| Q-203 | Кнопка редактирования при листании | Едет вместе со страницей, на соседней странице есть своя — страница выглядит целиком |
| Q-204 | Где одна кнопка «Добавить виджет»? | Первая свободная четверть по порядку чтения, без неё — первая свободная мелкая клетка |
| Q-205 | «Не помещается» — это край сетки или другие виджеты? | Край сетки: высота подрезается. На занятое место — как раньше, занятые виджеты переезжают |
| Q-206 | Сворачивать группы приложений? | Нет: группа — заголовок и горизонтальная лента, без лишнего нажатия |

## Проверки
- **AC-55.1.** Given больше одного спейса, When вести палец по нижней плашке, Then край страницы на каждом шаге под пальцем, слева текущий спейс, справа — настоящий экран соседа с его палитрой; после переключения подмены не видно.
- **AC-55.2.** Given свайп закончился, Then обои соседей освобождены; следующий свайп загружает их заново.
- **AC-55.3.** Given режим редактирования и свободное место, Then видна ровно одна кнопка «Добавить виджет».
- **AC-55.4.** Given высокий виджет в режиме редактирования, When сразу (без удержания) перетащить его так, что он не помещается до низа, Then после отпускания он стоит в выбранной строке и стал ниже ровно настолько, чтобы поместиться.
- **AC-55.5.** Given выбор виджета, Then виджеты сгруппированы по приложениям, часы первыми, у каждого — превью.

Unit: одна ячейка добавления, подрезка высоты при переносе, порядок групп. UI API 36: край страницы под пальцем (по пикселям), короткое отпускание без переключения, одна кнопка добавления, перенос без удержания с подрезкой. Вид превью и плавность — вручную на эмуляторе.
