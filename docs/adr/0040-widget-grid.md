# ADR-0040. Сетка 2×2 с растягиванием виджетов

Статус: принято по указанию владельца, 2026-11-08. Выпущено в 0.9.1. Заменяет решения 1, 3, 5 и 6 ADR-0039 (режимы панели, порядок ячеек, перенос, формат v3); остальные решения ADR-0039 действуют.

## Контекст
В 0.9.0 панель имела режимы «Стандартная» (до двух в ряд или колонку) и «Расширенная» (2×2), а виджет всегда занимал одну ячейку. Владелец попросил полноценную сетку: одна колонка во всю высоту рядом с двумя ячейками, виджет во всю ширину и так далее, с переносом и растягиванием прямо на главном экране. Выбранные варианты: сетка фиксированно 2×2, ручки на всех краях, содержимое ячейки по-прежнему по центру.

## Решения
1. Панель — одна сетка 2 колонки × 2 строки. Режимы «Стандартная/Расширенная» и «В ряд/В колонку» удалены вместе с их строками в минимодалке «Виджеты». Каждый виджет (и часы) занимает прямоугольник: 1×1, 2×1, 1×2 или 2×2; прямоугольники не пересекаются.
2. Вне редактирования строки без виджетов не занимают места; пустая панель не видна. В редактировании видны обе строки, каждая свободная ячейка — ячейка «Добавить виджет»; нажатие добавляет виджет именно в неё (ячейка запоминается и для штатных экранов привязки и настройки). Добавление из минимодалки «Виджеты» занимает первую свободную ячейку.
3. Перенос: удержание по системному таймауту и перетаскивание. Рамка-превью показывает, куда встанет виджет с тем же размером; при отпускании он встаёт туда.
4. Растягивание: на каждом крае, который можно сдвинуть, — полоска-ручка цвета акцента. Перетаскивание ручки меняет размер с привязкой к ячейкам, рамка-превью показывает новый прямоугольник. Ручки не показываются у краёв, упирающихся в границу сетки, если виджет и так в одну ячейку по этой оси. Полоска лежит на непрозрачной подложке темы с контуром (ADR-0021).
5. Конфликты разрешаются вытеснением: виджеты, которые накрывает новый прямоугольник, переезжают в свободное место: сначала туда, где стоял перемещаемый виджет, затем в первую свободную ячейку, сначала с прежним размером, затем в одну ячейку. Если места нет, изменение не применяется. Так перенос на занятую ячейку меняет виджеты местами.
6. Accessibility-действия «Переместить раньше/позже» двигают виджет по ячейкам в порядке чтения с сохранением размера. «Увеличить» растягивает на одну ячейку (вправо, вниз, влево, вверх — первое возможное), «Уменьшить» сжимает с правого или нижнего края.
7. Формат виджетов v4 хранит для каждого виджета колонку, строку и размеры, для ожидающей привязки — целевую ячейку. v1–v3 читаются: виджеты раскладываются по ячейкам в прежнем порядке строка за строкой, стандартная колонка остаётся колонкой. Сетка вмещает четыре ячейки. Если записей больше (было возможно только в старых форматах), сначала убираются встроенные часы: их можно вернуть в один шаг, а настроенный виджет — нет. Виджеты сверх четырёх после этого отбрасываются, их id освобождаются при запуске. Повторяющиеся id в старом формате считаются повреждением, как и в v4. Снимок главного экрана использует тот же кодек.
8. Размер, который получает виджет Android, — фактический размер прямоугольника. Виджеты меньше прямоугольника центрируются.
9. Новых зависимостей и разрешений нет.

## Проверки
Unit: прямоугольники, добавление, перенос с обменом, растягивание с вытеснением и сжатием, отказ без места, привязка ручек и переноса к сетке, видимые строки, миграция v1–v3. UI API 36: свободные ячейки добавления, обмен переносом, растягивание на две строки, перезапуск, полная сетка без ячеек добавления. Визуальный просмотр в эмуляторе.
