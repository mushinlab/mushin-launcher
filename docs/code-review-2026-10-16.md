# Ревью кода перед публикацией в Google Play

Дата: 2026-10-16, исходный коммит ea70ac5. Вопрос владельца: соответствует ли приложение конвенциям Android-разработки и можно ли честно назвать код читаемым и поддерживаемым.

Два независимых ревью. Claude: метрики и выборочное чтение кода, находки C1–C6. Muse, через оркестрацию Orca: сначала свой аудит, не видя находок Claude (R1–R17), затем проверка находок Claude. Решения владельца по спорным пунктам — в [ADR-0015](adr/0015-code-quality.md).

## Сверка
- У Claude подтверждены все 12 пунктов. Две поправки в подсчётах: подавлений `@Suppress` было 5, а не 3; инструментальных тестов 56 без модуля бенчмарков.
- У Muse не приняты две находки:
  - R10 «минутный тик перерисовывает весь главный экран». `HomeScreen` получает `State<Long>`, значение читают только `ClockTime`/`ClockDate` (`Clock.kt`), поэтому перерисовываются одни часы.
  - R11 «расстояния жестов в dp заданы в коде». AGENTS.md запрещает хардкодить только таймауты; они берутся из `viewConfiguration`, а расстояния — именованные поля `GestureConfig`.

## Проверено
- ktlint, detekt (0 находок), Android lint, `checkModuleGraph`, `checkReleasePermissions`.
- 313 тестов, из них 61 инструментальный: все 56 UI-тестов приложения и 5 тестов иконок на эмуляторе API 36.
- Сборка release, Baseline Profile перегенерирован.

## Что можно честно заявлять
> Modern Android stack (Kotlin, Jetpack Compose), modular architecture with enforced module boundaries, unidirectional state with the ViewModel and plain state holders, static analysis with standard thresholds (ktlint, detekt, Android lint) and 300+ unit and UI tests in CI.

Формулировка «readable and maintainable codebase» теперь подкреплена: состояние вынесено из Activity, у ViewModel есть тесты, detekt работает со стандартными порогами, у API `core` есть документация, и есть CONTRIBUTING для внешних участников.
